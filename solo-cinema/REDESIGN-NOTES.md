# Redesign and provider verification

The prior interface put discovery, search, results, player, manual source entry and watchlist into one long document. The new interface separates home/categories, search results, player and watchlist into navigable views. Selecting a search result starts source lookup immediately; the watchlist is optional. Episode selection remains on the player view. Back returns to the results. The hardcoded anime cards were removed; the anime view requests Cinemeta's Anime genre catalog. Category cards now open their selected title directly; they are not promises of a playable stream.

Search combines MovieBox, KissKh and Cinemeta results; exact title matches rank first. Matching MovieBox/Cinemeta entries merge only on exact title, media type and year (and compatible IMDb IDs). Same-named MovieBox entries of the same type and year are collapsed; the resolver already searches for alternative matching MovieBox subjects. Other uncertain duplicates remain separate rather than risk playing the wrong title. Cinemeta-only results resolve providers by IDs where possible; MovieBox lookup requires a unique exact title/type/year match. Artwork uses Cinemeta image URLs when matched, not a guessed image for every title. External image hosts see the client's IP.

New 7Movies/VidLink adapter uses the third-party encryptor described in the linked upstream project, a fixed API endpoint and the existing bounded, DNS-validated media proxy. Only referer and origin headers from the provider are forwarded, not arbitrary authorization/cookies. Captions are optional. The third-party encryptor sees the TMDB ID and host IP. No upstream source was copied.

Evidence from web retrieval in this session: Cinemeta's Anime catalog returned anime metadata; the VidLink encryptor returned an encrypted ID for Oppenheimer, and a subsequent VidLink API GET returned a 480p MP4 URL and caption metadata. No media bytes were played, no live API was called from the Botkeep server, and GET retrieval is not equivalent to an end-to-end browser test. A separate request to the Movy seed endpoint returned HTTP 500; no response details were available, so this does not establish why the user's deployment fails. The sandbox is restricted to GitHub and package registries; previous Chromium launch lacked NSS/NSPR libraries. Real desktop/mobile visual, playback and provider checks remain outstanding.

Not implemented: the supplied Vidsync, Videasy, Netmirror, Vidfast, 4KHDHub, VixSrc and FlyStream leads. The descriptions themselves say these are unverified and some require changing keys, tokens, cookie sessions, packed scripts, or a challenge-browser companion. Adding names without validated resolvers would misrepresent availability and could undermine the proxy's security boundaries. The underlying bot's separately documented downloader SSRF problem remains outside this UI change.
