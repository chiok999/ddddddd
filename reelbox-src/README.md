# ReelBox — the Troy interface

Source for the **ReelBox** mobile streaming UI. It started as a reconstruction of the
compiled build in `chiok999/reelbox`; it is now the interface Troy serves at `/`, wired
to Troy's real catalog, search, episodes and transcoder rather than to placeholder data.

The build is copied into `solo-cinema/app/dist/public/` and served by `solo-cinema`'s
existing server, so the deployment stays one process on one port with no build step on
the host. See `solo-cinema/UI.md` for the routing rules and the CSP requirements. The
original hand-written player has been deleted, so this is the only interface.

## Why this exists

The upstream repository only ships a compiled Nitro/TanStack Start bundle. The original
source was never committed, so the UI could not be edited or extended. This tree is a
faithful reconstruction: same routes, same catalog formulas, same tokens, same copy.

## Stack

- **TanStack Start** + **TanStack Router** (SSR, file-based routes)
- **React 19**
- **Vite 8** + `@vitejs/plugin-react`
- **Tailwind CSS v4** (`@tailwindcss/vite`, CSS-first config in `src/styles.css`)
- **lucide-react** for icons

## Layout

```
src/
  routes/
    __root.tsx        app shell, bottom nav, 404 + error views, head/meta
    index.tsx         home: hero carousel, tab filter, five rails
    browse.tsx        Explore: search, type/genre chips, poster grid
    ranking.tsx       Top: ranked list with outlined rank numbers
    title.$id.tsx     detail: backdrop hero, cast, seasons/episodes, "You may also like"
    watch.$id.tsx     player: controls, speed/quality menu, subtitles, up next
    me.tsx            My List, watch history, language, app links
  components/
    Header.tsx        logo, search link, premium mark
    PosterCard.tsx    poster + rating badge, link to detail
  lib/
    movies.ts         24-title catalog, sections, 8 actors, 6 countries
    library.ts        localStorage My List / history behind one `rb:lib` event
  styles.css          design tokens + custom utilities
public/favicon.ico
```

## Run it

```bash
npm install
npm run dev        # http://localhost:8792 -- against a Troy on :3000, or its own API mock
npm run build      # builds and publishes into ../solo-cinema/app/dist/public
npm test:engine    # 8 playback behaviours, mutation-checked
npm test:api       # request shapes against Troy's validation
```

`npm run dev` serves the shell alone; it has no API of its own, so sign-in and catalog
calls need a Troy running behind the same origin. For local UI work that is annoying, so
the checks above run against fixtures instead.

## How it connects

- `src/lib/api.ts` — every Troy endpoint the UI uses, in one place, so a failure has one
  shape. Bodies are asserted in `tools/api-check.mjs` against each handler's validation.
- `src/lib/playback.ts` — resolve → convert → play, ported from the original player with
  the original bug-and-rule comments kept. See `solo-cinema/UI.md`.
- `src/lib/item-store.ts` — catalog ids are bound to the session that fetched them and
  expire after an hour, so entries are kept in memory (mirrored to sessionStorage) rather
  than re-fetched by id, which Troy does not support.
- `src/lib/art.ts` — artwork through wsrv.nl, with the hostname allowlist the original UI
  used.
- `src/lib/library.ts` — My List and history on the original `rb:*` keys, progress and
  quality on Troy's existing `solo-*` keys, so the two UIs agree.

## Reconstruction notes

- `src/routeTree.gen.ts` is generated by the router plugin on first dev/build; it is not
  hand-maintained.
- The catalog is generated by formula, not data: title names, actors, countries, and the
  `rating`/`duration`/`seasons` expressions were transcribed exactly from
  `dist/server/_ssr/movies-*.mjs`, so the same 24 titles in the same order appear.
- Design tokens are stated in `oklch` because the original theme was authored there and
  gradient interpolation between the primary and accent depends on the colour space.
- Playback uses the same public sample video the original did; there is no real streaming
  backend, and the quality/speed menus are local UI state only.
- Style utilities (`.app-shell`, `.hero-fade`, `.rank-num`, `.range`, `.btn-primary`,
  `.btn-ghost`, `.glass`, `.bg-premium`, `.shadow-glow`) reproduce the custom rules from
  `dist/client/assets/styles-*.css`.
